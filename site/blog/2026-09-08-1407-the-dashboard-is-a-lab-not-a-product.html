The dashboard is a lab, not a product

2026-09-08 14:07 · toolingdashboard

The results page grew teeth: multiple engines, corpus records, smoke runs, mitigations, and enough HTML to break if treated casually.


Audio: brook.wav

The dashboard keeps the comparison tables and provenance visible. The repository does not pretend to be a production transcription service.

The dashboard is deliberately an evaluation surface. It shows the files that were actually tested, the engines that produced them, and the failures that did not. That makes it useful to me before it makes it pretty to anyone else.

The useful bit

The project is now called `localtranscription`, but its rule is unchanged from the first tiny test: keep the input explicit, keep the output inspectable, and do not turn a promising transcript into a claim the evidence cannot support.
